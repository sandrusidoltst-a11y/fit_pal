The diagnosis trail

  1. Initial finding (N=1): Bot says wrong plan targets — "120g protein / 150g carbs" instead of "140g / 250–300g".
  2. User's question: "Is this really plan-reading or just LLM variance?"
  3. Variance test (V1, N=5): 4/5 runs gave the same wrong "6 protein / 3 carb" target. PERSISTENT, not variance. Looked like a real prompt bug.
  4. Trace inspection: fetched the actual ChatOpenAI input. SystemMessage contained:
    ## User Nutrition Plan Daily targets: 1600 kcal, 120g protein, 150g carbs, 50g fat.
    — NOT the 12,127-char real plan we'd stored.
  5. Source of the fake summary: hardcoded at src/context.py:20 in DEFAULT_DEV_PROFILE. Activates whenever context.user_profile is missing.
  6. Architectural realization: the graph doesn't load user_profile from DB. The caller does (the bot gateway in production). Our test script only passed user_id, never user_profile — so the fallback kicked in silently.
  7. Fix: updated the test to fetch user_profile from DB and include it in the context, matching bot/gateway.py:_load_user_profile.
  8. Verification (V2, N=5): all five S4 runs now cite the correct plan targets; all five S2 runs return tight default. Both F1 and F2 close.

Architectural finding worth capturing

The graph doesn't load user_profile — the caller does

Discovered while diagnosing F1: ContextSchema in src/context.py defines user_profile as a field the caller must populate. In production, bot/gateway.py loads the profile from Supabase and includes it in the HTTP body's context.user_profile. The graph itself does not fetch user_profile.

This creates an asymmetry with daily_log_today, which IS loaded inside the graph by a node called load_daily_context. The asymmetry creates a silent footgun for any non-gateway caller (tests, Studio, future CLIs).

Possible future improvement: add a load_user_profile node to the graph mirroring load_daily_context. Tests, Studio, gateway — all simpler. The DEFAULT_DEV_PROFILE fallback could then become "no profile" (explicit) instead of a fake summary (silent wrong).

Out of scope for this loop. Worth an ADR conversation.
